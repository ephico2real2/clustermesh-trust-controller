# Local Podman image build, kind import, and security qualification

This is the repeatable local-first path for CMTC and the Cilium fork. It keeps
image building and the existing Kubernetes runtime separate:

```text
MacBook shell ──Podman connection──> Ubuntu build VM
     │                                  │
     │                           Linux ARM64 image archive
     │                                  │ shared /private/tmp
     └──────────────────────────────> Colima cmtc-cilium VM ──> existing kind cluster
```

Podman builds on the MacBook's selected Linux builder. The Cilium integration
lab is kind running in the separate Colima profile `cmtc-cilium`; the Cilium
fork image is transferred as a Docker archive and imported into kind's existing
container runtime. `podman load` on the build VM alone does not put an image into
the kind nodes.

The persistent local lab is the two-cluster mesh `cmtc-a` and `cmtc-b`; use
those clusters for CMTC, the Cilium fork, ztunnel and cross-cluster application
qualification. Do not create or rely on a separate `cmtc-mtls` cluster. Create
a temporary cluster only when a feature specifically needs a non-mesh topology,
and delete it after that test. Preserve unrelated Colima profiles and
containers. Finish affected local qualification before CI; CI remains deferred
by the active delivery instruction. Do not conflate CI coverage with publishing
an image to a registry.

## 1. Preflight the existing machines

Run from macOS. Select the Podman connection explicitly; do not change the
default connection to make a build work.

```bash
podman system connection list
podman --connection cmtc-ubuntu-build info \
  --format 'host={{.Host.OS}}/{{.Host.Arch}} cpus={{.Host.CPUs}} memory={{.Host.MemTotal}}'
colima list
colima -p cmtc-cilium status
```

The selected target for this Apple Silicon lab is `linux/arm64`. An AMD64 build
is a separate qualification and must use `linux/amd64`. Require the builder to
be reachable and the existing Colima profile to be healthy before deployment.
If either reports unavailable or Broken, stop before running `kind load`, Helm,
or cluster mutation commands. Diagnose the existing VM and preserve its disk;
do not switch kind providers or recreate retained clusters as a workaround.

On 2026-10-24, the restricted shell first returned `operation not permitted`
for the Podman socket and showed a false `Broken` status for Colima. A direct,
read-only host check confirmed the `cmtc-ubuntu-build` builder is Linux ARM64
with 8 CPUs and 16 GiB memory, and `cmtc-cilium` is Running with its existing
Docker runtime on Ubuntu 24.04.4 LTS (Colima 0.10.3). The persistent lab
consists of the four kind nodes in `cmtc-a` and `cmtc-b`, plus the existing
BuildKit container. If the default sandbox again returns a socket permission
error, verify through the authorized host command path before calling the VM
broken.

Kind's configuration supports pod/service subnets and API-server settings, but
does not assign a static Docker-network IP to each node. The lab discovers all
node addresses on Docker's `kind` network and configures them as ClusterMesh
NodePort peers. After Colima restarts, run
`scripts/lab/reconcile-clustermesh-endpoints.sh` before relying on cross-cluster
traffic; it refreshes both Helm releases only if those addresses changed. See
[Kind ClusterMesh recovery](KIND_CLUSTERMESH_RECOVERY.md).

## 2. Build a Cilium agent image with Podman

For the current Cilium agent-only work, compile the agent in the pinned Go
builder and overlay that binary on the digest-pinned fork runtime image. This is
the local method used for the CNI/ZDS changes. It does not rebuild Cilium's BPF
objects or the operator and ClusterMesh API server. Build those components
separately when their source changes.

Run on the MacBook. Keep the build source at an exact commit and retain all
source edits in that commit before recording a source pin.

```bash
set -euo pipefail

PODMAN_CONNECTION=cmtc-ubuntu-build
CILIUM_SOURCE=/private/tmp/cilium-ztunnel-authorization-runtime
ARTIFACT_ROOT=/private/tmp/cmtc-ztunnel-build-tools
GO_CACHE=/private/tmp/cilium-ztunnel-linux-go-cache
BASE_IMAGE=ghcr.io/ephico2real2/cilium-dev@sha256:15cc5402e93416e8ff71f24b79b0fc1e6b3837f0c4c216b0eb377b8d47b92d68

SOURCE_SHA=$(git -C "$CILIUM_SOURCE" rev-parse HEAD)
if [ -n "$(git -C "$CILIUM_SOURCE" status --porcelain --untracked-files=all)" ]; then
  echo 'Commit the Cilium source changes and clear untracked files before building an exact-source image.' >&2
  exit 1
fi
SHORT_SHA=${SOURCE_SHA:0:10}
IMAGE="localhost/cilium:cni-admission-${SHORT_SHA}"
CONTEXT="$ARTIFACT_ROOT/agent-context-${SHORT_SHA}"
mkdir -p "$CONTEXT" "$GO_CACHE"
mkdir -p "$ARTIFACT_ROOT"

# Cilium reads this generated version metadata when building outside Git's
# normal Docker build context. The file is ignored/generated by the checkout.
printf '%s %s\n' "$SHORT_SHA" "$(git -C "$CILIUM_SOURCE" show -s --format=%cI HEAD)" \
  > "$CILIUM_SOURCE/GIT_VERSION"

podman --connection "$PODMAN_CONNECTION" run --rm --platform linux/arm64 \
  --cpus 2 --memory 3g --security-opt label=disable \
  -e GOMAXPROCS=2 -e GOMEMLIMIT=1536MiB -e GOFLAGS=-p=2 -e GOCACHE=/cache \
  -v "$CILIUM_SOURCE:/src" -v "$GO_CACHE:/cache" -w /src/daemon \
  docker.io/library/golang@sha256:162be5298a40ed317005c8339c6de4d10d3eef336d66dc8e9259b03ab9d3a6d2 \
  bash -ec 'make GIT_VERSION="$(cat /src/GIT_VERSION)" EXTRA_GO_BUILD_FLAGS=-buildvcs=false cilium-agent'

cp "$CILIUM_SOURCE/daemon/cilium-agent" "$CONTEXT/cilium-agent"
cat > "$CONTEXT/Containerfile" <<EOF
FROM $BASE_IMAGE
COPY cilium-agent /usr/bin/cilium-agent
EOF

podman --connection "$PODMAN_CONNECTION" build --platform linux/arm64 \
  --file "$CONTEXT/Containerfile" \
  --label "org.opencontainers.image.revision=$SOURCE_SHA" \
  --label org.opencontainers.image.source=https://github.com/ephico2real2/cilium \
  --tag "$IMAGE" "$CONTEXT"

podman --connection "$PODMAN_CONNECTION" image inspect "$IMAGE" \
  > "$ARTIFACT_ROOT/agent-image-${SHORT_SHA}.json"
podman --connection "$PODMAN_CONNECTION" run --rm --network none --memory 256m \
  --entrypoint /usr/bin/cilium-agent "$IMAGE" --version \
  > "$ARTIFACT_ROOT/agent-version-${SHORT_SHA}.txt"
rg -F "$SHORT_SHA" "$ARTIFACT_ROOT/agent-version-${SHORT_SHA}.txt"
podman --connection "$PODMAN_CONNECTION" save --format docker-archive \
  --output "$ARTIFACT_ROOT/agent-${SHORT_SHA}-linux-arm64.tar" "$IMAGE"
shasum -a 256 "$ARTIFACT_ROOT/agent-${SHORT_SHA}-linux-arm64.tar" \
  > "$ARTIFACT_ROOT/agent-${SHORT_SHA}-linux-arm64.tar.sha256"
```

The archive is a local handoff artifact, not a registry push. The image's
revision label, `podman image inspect`, image architecture, `cilium-agent
--version`, and archive checksum bind it to the selected source. The runtime
base digest comes from the checked-in development image lock; do not silently
replace it with a mutable tag.

The fork's `contrib/cmtc-images/build.sh` is a separate publisher helper: it
uses Docker Buildx and `--push` to GHCR. It is not the local-only procedure and
must not be used to publish during this mandate.

## 3. Import the archive into the persistent two-cluster mesh

The host and Colima guest share `/private/tmp`. Select the existing Colima
Docker runtime and import the exact archive into both retained clusters:

```bash
export DOCKER_HOST="unix://$HOME/.colima/cmtc-cilium/docker.sock"
export KUBECONFIG=/private/tmp/cmtc-a-b-20261024.kubeconfig
export ARTIFACT_ROOT=/private/tmp/cmtc-ztunnel-build-tools
export SOURCE_SHA="$(git -C /private/tmp/cilium-ztunnel-authorization-runtime rev-parse HEAD)"
export SHORT_SHA="${SOURCE_SHA:0:10}"
ARCHIVE="$ARTIFACT_ROOT/agent-${SHORT_SHA}-linux-arm64.tar"

test -s "$ARCHIVE"
rg -F "$SHORT_SHA" "$ARTIFACT_ROOT/agent-version-${SHORT_SHA}.txt"
for cluster in cmtc-a cmtc-b; do
  kind get clusters | grep -qx "$cluster"
  kind load image-archive "$ARCHIVE" --name "$cluster"
done
```

Loading only makes an image available to the kind nodes; it does not deploy
that image. Apply the exact local image override through the pinned Cilium
chart for the feature under test. Then verify the requested image and runtime
image IDs on every Cilium agent in both clusters. Refresh peer addresses and
wait for both ClusterMesh links:

```bash
bash scripts/lab/reconcile-clustermesh-endpoints.sh
for cluster in cmtc-a cmtc-b; do
  kubectl --context "kind-$cluster" get nodes -o wide
  kubectl --context "kind-$cluster" -n kube-system rollout status ds/cilium --timeout=5m
  kubectl --context "kind-$cluster" -n kube-system get pods -l k8s-app=cilium -o wide
  cilium clustermesh status --context "kind-$cluster" --wait --wait-duration 10m
done
```

Keep the Pod JSON, `podman image inspect`, version output and archive checksum
together. A kind/containerd `imageID` may use a runtime-generated import name;
record it alongside the Podman image config ID instead of assuming both IDs
have the same representation.

## 4. Run local tests, traffic, and evidence checks

Run the changed Go unit/race tests, privileged socket/network-namespace cases,
`go vet`, and the repository's configured lint before making the image. Confirm
the targeted tests actually executed and report selected/passed/skipped counts;
zero selected tests or skipped privileged cases are not a pass. Keep raw logs
and exit statuses in a fresh task-owned output directory.

Run the current two-cluster baseline against both mesh contexts:

```bash
bash scripts/lab/reconcile-clustermesh-endpoints.sh
bash scripts/lab/test.sh
```

The security-transition and first-Pod admission drivers under
`scripts/lab/mtls/` still contain assumptions from the retired isolated
`cmtc-mtls` fixture. Do not run them against the persistent mesh until each
driver explicitly selects and validates both `kind-cmtc-a` and `kind-cmtc-b`.
The local security report records prior bounded qualifications and open gates;
those results do not substitute for testing the current deployed images on the
two-cluster mesh.

For Grafana evidence, start real load first, validate live Prometheus responses
for the selected time window, and run the repository browser walk in light and
dark themes. Retain load JSON, counter/query vectors, browser logs and screenshots
in the same evidence set. Never relabel native TCP counters as HTTP requests or
TLS handshakes. The dashboard conventions and chart/panel checks are in the
[dashboard guide](../../DASHBOARD_GUIDE.md); the previous qualified local run is
documented in [LOCAL_SECURITY_VALIDATION.md](../../LOCAL_SECURITY_VALIDATION.md).

## CMTC operator image

The legacy image helper under `scripts/lab/mtls/build.sh` was written for the
retired isolated fixture. Do not use its `CMTC_MTLS_*` settings for the
persistent mesh. Build the CMTC image with the host Podman workflow, load its
archive into both clusters, then apply the repository manifests with the exact
image reference and verify both controller and node-agent rollouts in each
cluster. Loading an archive alone does not prove that a workload is running it.
