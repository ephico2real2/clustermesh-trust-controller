* A disconnected queue does retain canceled pending ADD markers. This is intentional restrictive state, not a missed success path: queued work remains potentially executable until the actual consumer resolves it. On reconnect, processUpdate checks the original request context before opening the FD or transmitting, then its deferred marker completion runs. Releasing the marker just because the producer canceled would recreate the pre-write absence race. If the proxy never reconnects, affected endpoints remain unavailable; no drain receipt is fabricated.
* Producer cancellation returns and releases the existing operation semaphore. A drain waiting on pending completion has the earlier caller deadline or the existing 30-second ZDS timeout and releases its semaphore on every return. The consumer does not acquire that semaphore, so reconnect can clear expired queue work while a drain waits. No endpoint/cache mutex is held during the channel join. Production result channels are buffered by one, so late completion cannot block on the departed producer.
* The production queue has capacity 100, the pending index has a hard 4096-entry cap, and uncertainty has 4096 slots with at most eight retained historical bindings each. Failure to enqueue clears only its pointer-token marker. History append clones before mutation and rejects overflow before replacing the retained latest binding; no unresolved owner is evicted. Normal ACK success prunes only same-original-owner capture generations no greater than the actual ACK, retaining the acknowledged binding and preserving newer/foreign uncertainty.
* Drain selection validates all retained full bindings; a conflicting reference, sandbox or execution cannot be silently skipped. Every candidate has the same original binding except capture generation. A fresh nonce is used per request under one overall deadline. A native nonempty NACK only advances this bounded exact history; it never creates a receipt. Generic ACK, wire error, changed epoch, cancellation and mismatched binding/generation/nonce abort without fallback. Root peer credentials, same-execution HELLO epoch and single-consumer serialization remain unchanged.
* Successful retirement removes only the frozen full-binding selection. Newly recorded successor/foreign bindings remain. Policy quarantine confirmation retains ownership and capture; it does not retire or reopen the incarnation. The real Rust owner checks exact binding before task deletion and supports same-generation, fresh-nonce retry after a lost receipt. Missing/restarted original ownership is not interpreted as successful drain.

Remaining explicit limits: process-local uncertainty does not establish restart durability; a different proxy execution cannot prove old task drain; pending queue cleanup requires a consumer; no source-IP kernel reachability, first-packet/restore fence or HBONE transport grant is supplied by this increment. Existing unexpected listener-accept failure can stop future accepts and is a prior availability limitation, not introduced by this patch or a reason to infer absence.
