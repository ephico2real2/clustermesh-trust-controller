# Existing Cilium lab review — 2026-10-23

## Confirmed target and review boundary

The user confirmed the primary CMTC target: **ztunnel provides workload mTLS; WireGuard or IPsec provides the node transport encryption underneath; acceptance proves the complete cross-cluster path.** Neither layer substitutes for the other. No-transport and mTLS-off profiles remain useful controls, not the production target. Whether arbitrary host/control-plane traffic is encrypted must be separately specified and tested; enabling pod transport encryption is not a universal host-traffic guarantee.

Reference repository: [ephico2real2/cilium-implementation-poc](https://github.com/ephico2real2/cilium-implementation-poc), main commit [`22fb6e14c0cca8c78af1f072d1e89ebaea6a916b`](https://github.com/ephico2real2/cilium-implementation-poc/commit/22fb6e14c0cca8c78af1f072d1e89ebaea6a916b), observed 2026-10-23. This review read source and recorded evidence; it did not deploy, inspect live clusters, run workflows, download private keys or modify that repository. Historical demo results are evidence to reproduce, not new CMTC test results.

A local checkout exists on another branch with unrelated work. Its CodeGraph CLI lacks `explore` and the available indexed context/file tools could not open the database. Review therefore used the immutable GitHub snapshot, without rebuilding the index or changing that checkout.

## What the workflow actually builds

[lab-observability.yaml](https://github.com/ephico2real2/cilium-implementation-poc/blob/22fb6e14c0cca8c78af1f072d1e89ebaea6a916b/.github/workflows/lab-observability.yaml#L14-L85) runs the shared `scripts/lab-up.sh poc1 poc2` path, then builds the sample images, installs observability stacks and applications, drives audited traffic, generates/applies policies, drives enforced traffic and captures the report/dashboard evidence. It preserves failure artifacts and tears the lab down. The [multi-cluster connectivity step](https://github.com/ephico2real2/cilium-implementation-poc/blob/22fb6e14c0cca8c78af1f072d1e89ebaea6a916b/.github/workflows/lab-observability.yaml#L209-L258) is optional and defaults off; future CMTC encryption qualification must make the required security/connectivity checks mandatory.

The larger local `clusters/poc1.yaml` has three control planes and two workers. These are distinct capacity profiles, not contradictory node counts.

## Existing failure cases to preserve

Demo 13 records that the agent's ClusterMesh object can exist with a nonzero cluster ID even when mesh enable/config values are turned off, and that ztunnel validation then rejects startup. This is an older experiment, not a complete v1.20.4 proof. Add tests distinguishing “has a cluster ID,” “has a ClusterMesh object” and “has active remote peers.” Merely changing the rejection to inspect peer count would still leave cross-cluster functionality unimplemented.

Its L4 test allowed an application port but observed HBONE on 15008 being denied, including the intended allowed peer. Its L7 experiment also timed out. Carry those into regression tests; opening 15008 broadly cannot count as preserving application-port authorization. If an existing L7 feature is outside an initial supported profile, reject that profile explicitly and retain its baseline regression coverage.

Demo 39's Deployment/StatefulSet display name is observability metadata. It is not the SPIFFE namespace/service-account identity or evidence of authority to speak for another cluster.

## Incremental end-to-end harness

1. **Reproduce controls in isolated disposable clusters.** Derive the small CI shape from the pinned lab, preserve non-overlapping CIDRs and explicit cluster IDs, and keep the full observability stack as a later layer. Record exact chart, agent/operator/proxy images, CRDs, kernel and settings. Provide a protected-root/cluster-intermediate fixture instead of invoking the original root-copy bootstrap.
2. **Verify trust consumers separately.** Test ClusterMesh API TLS, Hubble client mTLS and SPIRE-issued ztunnel workload SVIDs against their intended identities/authorities. Confirm unauthorized identities fail. Keep required workload peer trust narrowly scoped.
3. **Establish secure HBONE across the mesh.** Test both directions, direct pod IP, Global Service translation, different-node placements and duplicate namespace/service-account names across clusters. Verify expected peer identity and allowed/denied application ports. Keep the incompatibility guard for configurations that cannot meet the contract.
4. **Add WireGuard underneath.** For the same workload flow and time window, collect TLS peer/authorization evidence and independent WG peer state plus an underlay capture. Removing a required WG key must deny the protected flow even when HBONE could otherwise connect. Test explicit host-node traffic separately.
5. **Add IPsec underneath.** Repeat with XFRM states/policies, key loss/rotation, capture and MTU/MSS checks. Do not infer it from the WG profile.
6. **Exercise lifecycle and platform safety.** Stress pod/namespace creation/relabel/recreation, proxy/SPIRE/Cilium failures, partitions, stale observations, trust rotation and restart. No plaintext first packet or fallback; API, DNS UDP/TCP, webhooks and other declared platform paths remain healthy.
7. **Apply observability/release gates.** Make security-negative results fail the job; preserve evidence before teardown; run the required multi-cluster suite. Test metric freshness/absence and all nine CMTC dashboards against actual exporters. The lab's own nine dashboards and CMTC's nine proposals are separate artifacts.

The inner logical path is application → local ztunnel/HBONE TLS → Cilium-managed WG or IPsec transport → remote ztunnel peer verification → destination. Hook ordering and how this is represented in eBPF/encapsulation are still implementation questions; the diagram is not packet-trace evidence. Both inner identity/authorization and outer required transport must pass for a successful end-to-end result.
