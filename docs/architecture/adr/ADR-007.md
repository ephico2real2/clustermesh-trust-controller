# ADR-007: Kubernetes and OpenShift safety

**Status:** Proposed; decision direction from static source review on 2026-10-23, current state added 2026-10-25. Architecture/security approval pending.

## Decision direction

Never auto-enroll system/control-plane/infrastructure namespaces or hostNetwork components through ordinary policy. Preserve API, etcd, DNS UDP/TCP, kubelet, webhook, ingress, OAuth, operator and hosted-control-plane traffic through narrow verified contracts.

## Source evidence and gaps

V03 skips missing netns paths. Pinned documentation in V07/G06 does not support enrolled↔non-enrolled workload traffic. Excluding platform namespaces alone cannot establish application-to-platform safety. No OpenShift CNI/SCC/upgrade profile is tested.

## Alternatives and trade-offs

Compare explicit platform profiles with automatic discovery; namespace prefixes alone are insufficient. Missing or ambiguous inventory blocks rollout. Platform classification must not create a blanket policy bypass.

## Current state (2026-10-25)

- **Open failure:** DNS from enrolled Pods times out in both clusters, while unenrolled Pods resolve. Diagnosed: the native HBONE-only egress gate drops the plaintext query to CoreDNS (`bpf_lxc.c:1626`). A resolver-exception fix is in progress and not deployed. See the [test matrix](../SECURITY_AND_FAILURE_TEST_MATRIX.md).
- Source fact, separate from that failure: the native quarantine gate in our Cilium fork has no plaintext exception for host probes, DNS, world, CIDR or remote-node traffic; an approved resolver binding and a typed egress exception map are listed there as open dependencies (`bpf/lib/ztunnel_admission.h:32-35`).
- The deployed ztunnel's strict mesh egress has an empty exception list (`MESH_EGRESS_CONFIG` in the DaemonSet).
- No OpenShift profile is tested.

## Acceptance gates

Pin a Cilium-enabled Kubernetes/OpenShift topology and permissions. Test critical paths, bootstrap, upgrades and recovery while retaining application denials. Canary degradation stops progression. Rollback requires observed datapath/platform recovery and cannot authorize plaintext to protected peers.

Evidence IDs refer to the [Cilium v1.20.4 audit](../../research/SOURCE_AUDIT.md). The current-state section reports deployed and tested facts; it does not claim `Protected` or qualify any gate below. Mark Accepted only after explicit architecture/security approval.
