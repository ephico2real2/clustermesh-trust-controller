# ADR-007: Kubernetes and OpenShift safety

**Status:** Proposed; updated from static source review on 2026-10-23. Architecture/security approval pending.

## Decision direction

Never auto-enroll system/control-plane/infrastructure namespaces or hostNetwork components through ordinary policy. Preserve API, etcd, DNS UDP/TCP, kubelet, webhook, ingress, OAuth, operator and hosted-control-plane traffic through narrow verified contracts.

## Source evidence and gaps

V03 skips missing netns paths. Pinned documentation in V07/G06 does not support enrolled↔non-enrolled workload traffic. Excluding platform namespaces alone cannot establish application-to-platform safety. No OpenShift CNI/SCC/upgrade profile is tested.

## Alternatives and trade-offs

Compare explicit platform profiles with automatic discovery; namespace prefixes alone are insufficient. Missing or ambiguous inventory blocks rollout. Platform classification must not create a blanket policy bypass.

## Acceptance gates

Pin a Cilium-enabled Kubernetes/OpenShift topology and permissions. Test critical paths, bootstrap, upgrades and recovery while retaining application denials. Canary degradation stops progression. Rollback requires observed datapath/platform recovery and cannot authorize plaintext to protected peers.

Evidence IDs refer to the [Cilium v1.20.4 audit](../../research/SOURCE_AUDIT.md). No runtime capability is claimed. Mark Accepted only after explicit architecture/security approval.
