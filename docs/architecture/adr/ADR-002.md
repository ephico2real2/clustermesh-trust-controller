**Status:** Proposed; decision direction from static source review on 2026-10-23, current state added 2026-10-25. Architecture/security approval pending.

## Decision direction

Preserve Option A: protected organizational root, cluster-specific intermediates, SPIRE X.509-SVID issuance, cert-manager UpstreamAuthority and trust-manager public bundles. Never distribute root signing keys to clusters, nodes or namespaces. CMTC receives neither workload nor CA private keys.

## Source evidence and gaps

V08/V09 show real SPIRE registration support and a separate built-in CA with on-disk signing material. Reuse SPIRE enrollment, not the example root-key distribution. The pinned SPIRE cert-manager plugin reference confirms an intermediate-signing interface, not a deployed hierarchy.

## Alternatives and trade-offs

A common root and distinct intermediates do not prevent foreign-cluster impersonation. Compare cluster-specific trust domains with an explicitly cluster-bound identity/verifier scheme. Choose constraints, issuer, hierarchy and reload protocol explicitly.

The [mesh comparison](../../research/MESH_MTLS_COMPARISON.md) confirms the proxy's identity parser uses only trust-domain/namespace/service-account and its inbound verifier currently requires the same trust domain. Per-cluster domains therefore require an approved-peer verifier change; inserting a cluster path also requires parser/issuer changes. Neither is a configuration-only fix.

## Current state (2026-10-25)

- Option A is deployed: a host-held organization root, a separate SPIRE cluster CA per cluster, cert-manager signing the SPIRE CA, and exact SPIRE signers ([PKI trust flow](../../../PKI_TRUST_FLOW.md)).
- The lab uses cluster-specific trust domains, `cmtc-a.mesh.example` and `cmtc-b.mesh.example` (ztunnel DaemonSet `TRUST_DOMAIN`, read 2026-10-25).
- The same-trust-domain limit above describes the pinned upstream proxy and is historical for our fork. Our ztunnel fork verifies each peer against the exact approved signer for the trust domain in its authenticated SAN, with no fallback to the organization root (`src/tls/workload.rs:389-400` at `f221f29b59`).
- Cross-cluster traffic passes with these identities. The foreign-intermediate impersonation test, rotation and emergency revocation have not run.

## Acceptance gates

Pin deployment versions and prove external CA endpoint attestation, cluster-bound issuance/verification, key isolation and old+new consumer reload. A compromised foreign intermediate fails the impersonation test. Separate emergency revocation from routine rotation.

Evidence IDs refer to the [Cilium v1.20.4 audit](../../research/SOURCE_AUDIT.md). The current-state section reports deployed and tested facts; it does not claim `Protected` or qualify any gate below. Mark Accepted only after explicit architecture/security approval.
