**Status:** Proposed; decision direction from static source review on 2026-10-23, current state added 2026-10-25. Architecture/security approval pending.

## Decision direction

CMTC coordinates desired policy, public trust and rotation. Cilium owns packet enforcement; SPIRE issues SVIDs. Keep CMTC and Cilium control-plane extensions in Go (Hive inside Cilium; controller-runtime for the operator). Preserve no Linkerd or Istio; do not add another mesh control plane or proxy.

## Source evidence and gaps

V01/V11 establish the ClusterMesh guard and a Rust Cilium ztunnel dependency with Istio origins. Existing Cilium ztunnel is the proposed native path; whether its dependency fits the no-Istio requirement needs explicit review without silently changing the constraint. Go-only cannot describe every upstream component.

The user authorized studying Istio and Linkerd for reusable design patterns. The [comparison](../../research/MESH_MTLS_COMPARISON.md) adds no mesh deployment dependency. It identifies missing-policy admission and cross-domain verification behavior in Cilium's existing Rust proxy; track necessary proxy fixes explicitly alongside Go/Hive integration.

## Alternatives and trade-offs

Compare a minimal standalone operator with embedding all coordination in Cilium. Reject operator-only enforcement claims. Review the dependency boundary before committing to a proxy fork.

## Current state (2026-10-25)

- The boundary holds in the deployed lab: CMTC publishes intent and approved public issuer profiles; the Cilium fork owns capture, policy, the quarantine gate and xDS; SPIRE issues SVIDs; ztunnel does workload TLS. No Istio or Linkerd control plane runs.
- The upstream ClusterMesh/ztunnel rejection (V01) is replaced in our Cilium fork by a capability check that requires strict mTLS, a SPIRE CA, effective-policy quarantine, authenticated remote workload membership and issuer-profile pins (`pkg/ztunnel/cell.go:73`).
- The Rust proxy changes this ADR asked to track are in our ztunnel fork: an empty ALLOW set denies a protected workload, unknown mesh destinations are refused, and each peer is verified against the exact approved signer of its trust domain. See the [Cilium/ztunnel contract](../CILIUM_ZTUNNEL_CONTRACT.md).
- The no-Istio dependency review of ztunnel itself has not been recorded.

## Acceptance gates

An architecture/security reviewer accepts ownership and the dependency boundary. Upstream work identifies discovery, identity, authorization and packet-gate changes; retain the guard for unsupported combinations. Design approval is not production qualification.

Evidence IDs refer to the [Cilium v1.20.4 audit](../../research/SOURCE_AUDIT.md). The current-state section reports deployed and tested facts; it does not claim `Protected` or qualify any gate below. Mark Accepted only after explicit architecture/security approval.
