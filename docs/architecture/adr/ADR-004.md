# ADR-004: Namespace policy precedence

**Status:** Proposed; updated from static source review on 2026-10-23. Architecture/security approval pending.

## Decision direction

Apply platform protection → explicit exclusion → explicit selection mode → owned label reconciliation → observed enforcement. Support AllEligible and MatchSelectors; OR across selectors, AND within each selector. Use existing LOB/mnemonic metadata. Exclusions never grant access to protected destinations.

## Source evidence and gaps

V02 verifies the native label; CMTC precedence, admission and field ownership are unimplemented. Cilium's shown table keys by namespace name; CMTC must bind namespace UID and generation separately.

## Alternatives and trade-offs

Require a declared selection mode. Define empty/invalid selectors, multiple-policy conflicts, reserved-label/exemption permissions and GitOps ownership before generating CRDs. Do not remove another actor's labels.

## Acceptance gates

Unit/envtest cases cover precedence, selectors, UID recreation, relabeling, drift and ownership. Unsupported enforcement blocks live label changes; label success never becomes Protected. Missing platform inventory or conflicts produce explicit reasons.

Evidence IDs refer to the [Cilium v1.20.4 audit](../../research/SOURCE_AUDIT.md). No runtime capability is claimed. Mark Accepted only after explicit architecture/security approval.
