# ADR-003: Encryption composition

**Status:** Proposed; updated from static source review on 2026-10-23. Architecture/security approval pending.

## Decision direction

Treat workload HBONE mTLS and node transport encryption as distinct requirements. Target none, WireGuard or IPsec with mTLS on/off; reject unsupported mixed modes and prevent downgrade of either required layer.

## Source evidence and gaps

V10 shows mutually exclusive chart encryption branches and pod-netns TCP redirection. The complete eBPF/WireGuard/XFRM ordering remains untraced and untested; no dual-encryption configuration recipe is established.

## Alternatives and trade-offs

Do not enable independent internal flags and assume compatibility. Compare upstream separation of the configuration axes with the existing single-mode model; preserve the supported ClusterMesh baseline with mTLS disabled.

## Acceptance gates

Trace identity/marks, socket-LB, routing and reverse NAT. Pass independent TLS and WG/XFRM/capture checks, key-loss/strict-encryption tests, overlay/direct routing and MTU/MSS tests. TLS success alone cannot prove node encryption. UDP stays outside workload-mTLS scope.

Evidence IDs refer to the [Cilium v1.20.4 audit](../../research/SOURCE_AUDIT.md). No runtime capability is claimed. Mark Accepted only after explicit architecture/security approval.
