# ADR-005: Node agent design and the per-node eBPF measurement plane

<!-- /CMTC_DOC_CONTEXT -->

**Status:** Proposed. Revised 2026-10-25 by operator mandate; the previous direction (2026-10-23) is superseded. Architecture/security approval pending.

## Mandate (operator, 2026-10-25)

The eBPF programs in the CMTC node DaemonSet are the **measuring glue** of the mesh. On every node they capture metrics and insight about the datapath, enrollment, capture, authorization, TLS, withdrawal and recovery. The DaemonSet exports them.

This replaces the earlier direction, which treated the DaemonSet eBPF as "a development stage" that "must not become a permanent independent datapath". The measurement plane is permanent. What stays forbidden is any second **decision** path: the plane measures, it never decides.

## Decision

1. **Two roles, kept apart.**
   - **Verdicts:** Cilium owns packet enforcement, service translation, native policy and the workload quarantine gate (`bpf/lib/ztunnel_admission.h`, `pkg/endpoint/ztunnel_policy*.go` in the fork). ztunnel owns workload TLS and authorization.
   - **Measurement:** the CMTC measurement plane owns per-node observation.
   - The two roles never share a program, a map or a decision. The measurement plane does not open Cilium or ztunnel maps, even read-only.
2. **Observe-only, provably.** Every measurement program returns the hook's pass value on every path. The kernel enforces this for some hooks and not for others:
   - TCX: `TCX_NEXT` (-1). The verifier does not check `SCHED_CLS` return values (`kernel/bpf/verifier.c:15328-15329`, v6.8). Before Cilium's link, any other value ends the chain (`net/core/dev.c:3973-3977`): `TCX_PASS` (0) delivers the packet without Cilium's policy and admission gate, `TCX_DROP` drops it.
   - `cgroup_skb` and cgroup `sock_addr` hooks: 1. The verifier limits the value to 0 or 1 (0 to 3 for `cgroup_skb` egress, `verifier.c:15255-15275`), and one 0 in the effective array denies (`kernel/bpf/cgroup.c:56-57`).
   - `sock_ops`: no verdict, but TCP reads the reply of several callbacks (`include/net/tcp.h:2579-2601`, `TIMEOUT_INIT`, `RWND_INIT`, `NEEDS_ECN`). A measurement program answers no callback.
   - tracing: the verifier limits `fentry`, `fexit` and BTF raw tracepoints to 0 (`verifier.c:15282-15291`). It does not check `tp_btf` or `fmod_ret` (`:15293-15295`); the kernel discards the value of a raw or BTF tracepoint program (`kernel/trace/bpf_trace.c:2381`). `fmod_ret`, writable raw tracepoints, kprobe override and `freplace` (`verifier.c:15324-15329`) change kernel behavior and are not used.

   Beyond the return value, no measurement program:
   - writes a context field (TC: `mark`, `tc_index`, `priority`, `tc_classid`, `cb`, `tstamp`, `queue_mapping`; `cgroup_skb`: `mark`, `priority`, `cb`, `tstamp`; `sock_addr`: the socket address and port; `net/core/filter.c:8879-8897, 8620-8633, 9082-9113`). A TCX program that returns `TCX_NEXT` can still change the `mark` that Cilium reads next;
   - calls a helper outside a read-only allowlist. `bpf_set_retval` (it sets the syscall result even when the program returns 1, `cgroup.c:1600-1607`), `bpf_setsockopt`, `bpf_bind`, `bpf_skb_ecn_set_ce`, and the store, change, adjust and redirect helpers are excluded;
   - writes a map that Cilium or ztunnel reads.

   With these rules a measurement fault loses data and does not change traffic. The rules are properties of the program code. The acceptance tests prove them, because the kernel does not enforce them for TCX.
3. **Packaged in the CMTC node DaemonSet.** The Pod has two containers and stays in the Pod network:
   - the node agent: unprivileged and unchanged. It is the only container with a Kubernetes API token and a network listener. It discovers enrolled workloads and exports the plane's metrics;
   - the measurement loader: UID 0 with only `CAP_BPF`, `CAP_PERFMON` and `CAP_NET_ADMIN`, RuntimeDefault seccomp, no privilege escalation and a read-only root filesystem. containerd's default profile allows `bpf` with `CAP_BPF` and `perf_event_open` with `CAP_PERFMON` (containerd v2.3.4 `contrib/seccomp/seccomp_default.go:744-755`). It has no API token and no network listener, and it mounts the host cgroup v2 hierarchy read-only. It refuses to start when its effective, permitted, inheritable, bounding or ambient set holds any other capability. It does not mount bpffs, because it pins nothing.

   Hooks that need the host network namespace (TCX on host veths: the kernel resolves the interface index in the caller's namespace, `kernel/bpf/tcx.c:12-20, 310-319`) or `CAP_SYS_ADMIN` (opening Cilium programs and links by ID, `kernel/bpf/syscall.c:4207, 5260`; `BPF_ENABLE_STATS`, `:5316`) are not in this container. `hostNetwork` is a Pod field, so TCX here would also move the node agent out of the Pod network. The lab-only observer and fence keep those hooks.

   The loader is written in Go with cilium/ebpf v0.22.0, which is already in `go.mod`, in the same module as the node agent.
4. **Node-wide and automatic.**
   - **Discovery:** the node agent lists the Pods on its node (`spec.nodeName`) and their namespaces from the Kubernetes API. A Pod is enrolled when it is not `hostNetwork` and its namespace carries `io.cilium/mtls-enabled=true`, the label the Cilium fork admits on (`pkg/ztunnel/admission/cell.go:408`). No operator-written per-Pod configuration is used.
   - **Identity checks:** the loader attaches to the Pod-level cgroup that kubelet names after the Pod UID, and records the cgroup ID (the directory inode). It checks the path and the ID again on every sample. A recreated cgroup is a new attachment. Zero or several candidate cgroups make the workload unavailable. Pod UIDs are not reused, so a path cannot carry the data of another Pod.
   - **Change:** cgroup hooks have no Cilium anchor. For the lab TCX observer, Cilium regenerates an endpoint by updating its link in place (`BPF_LINK_UPDATE`: same link ID, new program ID; Cilium `pkg/bpf/link.go:20-31`, kernel `tcx.c:203-243`). It does so on every agent restart and every ztunnel quarantine release (Cilium fork `pkg/endpoint/ztunnel_datapath_admission.go:151-159`). The observer follows that update and stops only when the link ID or the rest of the chain changes (`internal/datapath/observer_linux.go`, `verify`).
   - **Mismatch:** a mismatch makes that workload's data unavailable. It never attributes data to the wrong workload.
5. **An independent witness.** The plane checks enforcement without trusting the components it checks. It reads kernel and packet facts, not Cilium's or ztunnel's own claims. Its evidence never sets `Protected` alone; `Protected` still requires authenticated proxy and effective-policy state inside Cilium.
6. **Metric rules.**
   - **Labels:** bounded to cluster, node, namespace, direction and a fixed class set. Per-Pod detail goes only into a rate-limited event stream, never into metric labels.
   - **Absence:** an absent hook or exporter reports unavailable, never a healthy zero.
   - **One reporter:** each event has exactly one reporter. Signals Cilium, Hubble, ztunnel or SPIRE already export are reused, not counted again.
   - **Durations:** measured with the monotonic clock (`bpf_ktime_get_ns`). Freshness in userspace uses `CLOCK_MONOTONIC`. Wall time is attached only at export.
   - **Self-cost:** the plane reports its own cost and pressure: program run time and count, map occupancy, event loss and attach state. Run time and count come from the kernel's program statistics only while `kernel.bpf_stats_enabled=1`. Enabling them needs `CAP_SYS_ADMIN` (`syscall.c:5316, 5743`), which the loader does not hold, so they are reported unavailable otherwise.
7. **The CMTC fence becomes a lab qualification tool.**
   - **Kept for:** deny-path tests on disposable workloads.
   - **Production gate:** the gate it prototyped now lives natively in Cilium (point 1).
   - **Not allowed:** the fence is not the production gate, and it never becomes a dynamic allow controller.

## Candidate signals

The eBPF measurement review ranks these candidates. None is accepted until it passes the acceptance gates below.

| Signal | Candidate hook | What it adds |
| --- | --- | --- |
| Outer packets and bytes | TCX on the workload veth (today's observer, lab-only) | Volume per workload and direction |
| Egress outside the tunnel | `cgroup_skb` on the Pod cgroup, bounded L3/L4 classification; TCX on the host veth stays lab-only | Application sockets only: a TCP packet that leaves or reaches the application on a non-loopback device did not pass through ztunnel. UDP, DNS included, and ICMP are uncaptured by design and counted as such |
| Client DNS | `cgroup_skb` on the Pod cgroup, socket storage | Queries sent, answers, rcode, latency, resolver locality, and whether the query left the Pod; the only signal for a query dropped on the client's own node |
| Plaintext on 15008 | TCX, first payload record type only | A first record that is not a TLS handshake |
| Original application tuple | `cgroup/connect4`/`6`, `sendmsg4`/`6` | The destination and port the application asked for, hidden by the tunnel at TCX. These hooks run before Cilium's socket load balancer on the same socket, so they see the Service VIP |
| Connection quality | `sock_ops`, `sock:inet_sock_set_state`, `tcp:tcp_retransmit_skb` | Handshake latency, RTT, retransmits and resets, app-to-ztunnel and ztunnel-to-peer kept separate |
| Revocation window | Connection close joined with the agent's xDS ACK time | Measured time from a narrowed plan to the last packet of a closed connection |
| Drops outside Cilium | `skb:kfree_skb` with reason, enrolled namespaces only | Drops Cilium's own drop notifications do not count |
| Security events | Ring buffer, rate-limited | Per-incident detail without per-Pod metric labels |
| Self-measurement | `BPF_ENABLE_STATS`, map and ring-buffer counters | The plane's own cost and loss |

## Alternatives considered

- **Port the measurement into the Cilium agent.**
  - **Gains:** one loader, and Cilium-managed hook ordering.
  - **Costs:** the witness then shares a process with what it checks, which loses its independence.
  - **Not rejected.** It stays an option for individual signals that need Cilium's internal state. Hubble remains the source for flows it already covers. Hubble is disabled in the lab (`enable-hubble=false`).
- **No eBPF; component metrics only.** This cannot see the original application tuple, egress outside the tunnel, plaintext on 15008 or drops outside Cilium. Rejected.
- **Keep the eBPF as a temporary prototype** (the superseded direction). Rejected by the operator mandate.

## Risks

- **TCX ordering.** An external TCX program is not a stable Cilium extension API. Position and return value both matter. Before Cilium's link a program sees every packet, and any return value other than `TCX_NEXT` skips Cilium for that packet (`net/core/dev.c:3973-3977`). After Cilium's link it sees nothing, because Cilium's programs end the chain. The lab observer verifies the chain on every sample. The in-container loader uses no TCX.
- **cgroup multi-program semantics.** Confirmed in v6.8. Link attachments are always `BPF_F_ALLOW_MULTI` (`kernel/bpf/cgroup.c:1304-1305`). The effective array holds the cgroup's own programs first, then each ancestor's (`:401-439`), so a program on a Pod cgroup runs before Cilium's programs on the cgroup root for the same socket. Every program runs, and one 0 makes the result `-EPERM` (`:49-59`); `bpf_set_retval` sets the result even when a program returns 1 (`:1600-1607`). An attach on a Pod cgroup needs each ancestor attachment to allow it (`:372-393`); Cilium's link attachments do. When kubelet removes a Pod cgroup, the kernel detaches its links. A measurement program therefore returns 1, never calls `bpf_set_retval` and never writes the socket address, because Cilium's socket load balancer reads it next.
- **Attach-to-pin window.** The loader pins nothing. Its links live as long as its process: an exit, a crash or an uninstall detaches every program, and a restart attaches again (counters restart from zero). The fence keeps pinned links and documents its window (`LOCAL_DATAPATH_FENCE.md`).
- **Privilege.** The loader runs as UID 0 with `CAP_BPF`, `CAP_PERFMON` and `CAP_NET_ADMIN` and no other capability. It refuses to start when it holds any other effective capability. The node agent container stays unprivileged. The experimental observer and fence manifests use `privileged: true` (`config/experimental/datapath-observer.yaml:30-32`, `datapath-fence.yaml:35`); they need `CAP_SYS_ADMIN` for access by ID and must move to an explicit set.

## Acceptance gates

- **No verdict:** a test proves every program's return value on every path, and a static check of the compiled object finds no context write and no helper outside the allowlist. `BPF_PROG_TEST_RUN` returns the pass value for every packet class. Traffic is identical with the plane attached and detached.
- **Attribution:** node-wide discovery attaches only to enrolled workloads with matching frozen identity. Pod, IP, ifindex and sandbox reuse never misattribute data.
- **Recovery:** loader restart, Cilium agent restart and regeneration, node reboot and drain each end with every enrolled workload attached again, or reported unavailable.
- **Cardinality:** a bound on series per node, tested.
- **No double counting:** each metric's reporter is named in the metric contract (`observability/v2/metrics/`; until it lists them, the measurement-plane names are defined in one file, `internal/measurement/contract.go`), and no event is counted twice.
- **Freshness:** stale or absent data is unavailable on the dashboards.
- **Footprint:** run time and memory are measured under load and recorded.
- **Separation:** no signing-key access, identity minting, policy mutation or second traffic proxy.

## Evidence and open questions

- The current observer counts one frozen workload per node configuration (`internal/datapath/observer_linux.go:24-36`). The Pod UID is checked only as non-empty, and the namespace inode is the observer's own (host) namespace. It reads only `skb->len` and returns `TCX_NEXT` (`internal/datapath/bpf/observer.c`). The fence returns `TCX_DROP` unconditionally (`internal/datapath/bpf/fence.c`).
- At TCX, traffic of a ztunnel-enrolled Pod is HBONE to 15008. Upstream Cilium documents that "L4 policies won't work except for directly targeting the ztunnel HBONE port (15008)" ([ztunnel encryption](https://docs.cilium.io/en/latest/security/network/encryption-ztunnel/)). Only TCP is captured: the in-Pod rules redirect TCP only (fork `pkg/ztunnel/iptables/inpod.go:240-365`), so UDP, DNS included, and ICMP leave the Pod outside the tunnel and meet Cilium's admission gate.
- The lab sets `bpf-lb-sock=false`, but kube-proxy replacement turns the socket load balancer on (fork `pkg/kpr/kpr.go:47-49`; agent log `EnableSocketLB:true`). Cilium's cgroup programs at the cgroup root rewrite a Service VIP to a backend before the kernel connects. A CMTC hook on the Pod cgroup runs before them and sees the VIP; packet hooks see the backend. ztunnel's service lookup code (`src/state.rs:324`, `:356`) is not reached: the fork publishes workload addresses only (`pkg/ztunnel/xds/endpoint_event.go:327`).
- Answered by the eBPF measurement review: the first increment (socket-layer witness, client DNS, self-measurement, attribution); Go with cilium/ebpf; the Kubernetes API as the discovery source; the cgroup multi-program semantics.
- Open:
  - whether production adds TCX, which needs the host network namespace or a separate DaemonSet, and `CAP_SYS_ADMIN` for name checks;
  - whether the node owner enables `kernel.bpf_stats_enabled`.
