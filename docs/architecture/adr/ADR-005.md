# ADR-005: Node agent design

**Status:** Proposed; updated from static source review on 2026-10-23. Architecture/security approval pending.

## Decision direction

Retain hub/per-cluster Go controllers and a lightweight node DaemonSet for inventory, authenticated generation/digest ACKs and bounded probes. As a development stage requested by the user, evaluate a separately gated CMTC DaemonSet that loads a narrowly scoped eBPF observer/deny prototype; port the qualified production gate into the enhanced Cilium agent. Cilium remains the production owner of packet enforcement, service translation and policy. The prototype must not become a permanent independent datapath. Evaluate minimal Hive observation hooks supporting the agent.

## Source evidence and gaps

V02/V03/V11 show Cilium already owns endpoint inventory, enrollment, ZDS ACKs and the per-node proxy. A second enroller would duplicate authority. No stable external protection or bundle-consumption API was verified.

## Alternatives and trade-offs

Compare the transitional DaemonSet prototype with a direct Cilium Hive/loader implementation, measuring privilege, hook ordering, compatibility and footprint. Keep the current Observe DaemonSet unprivileged; put BPF access in a separately gated profile using only the capabilities and mounts required by the selected hook. Avoid unrestricted StateDB/debug and host filesystem access.

## Acceptance gates

Specify authentication, UID/generation/digest binding, freshness, RBAC, BPF map ownership, interface incarnation, CNI admission handshake and detach/recovery. Disconnected/stale agents cannot report fresh protection. No signing-key access, broad independent iptables/eBPF policy mutation, identity minting or second traffic proxy. A successful attach is not mTLS proof; the final gate must consume authenticated proxy and effective-policy state inside Cilium.

Evidence IDs refer to the [Cilium v1.20.4 audit](../../research/SOURCE_AUDIT.md). No runtime capability is claimed. Mark Accepted only after explicit architecture/security approval.
