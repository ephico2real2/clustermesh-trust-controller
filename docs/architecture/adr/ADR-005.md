# ADR-005: Node agent design and the per-node eBPF measurement plane

**Status:** Proposed. Revised 2026-10-25 by operator mandate; the previous direction (2026-10-23) is superseded. Architecture/security approval pending.

## Mandate (operator, 2026-10-25)

The eBPF programs in the CMTC node DaemonSet are the **measuring glue** of the mesh. On every node they capture metrics and insight about the datapath, enrollment, capture, authorization, TLS, withdrawal and recovery. The DaemonSet exports them.

This replaces the earlier direction, which treated the DaemonSet eBPF as "a development stage" that "must not become a permanent independent datapath". The measurement plane is permanent. What stays forbidden is any second **decision** path: the plane measures, it never decides.

## Decision

1. **Two roles, kept apart.**
   - **Verdicts:** Cilium owns packet enforcement, service translation, native policy and the workload quarantine gate (`bpf/lib/ztunnel_admission.h`, `pkg/endpoint/ztunnel_policy*.go` in the fork). ztunnel owns workload TLS and authorization.
   - **Measurement:** the CMTC measurement plane owns per-node observation.
   - The two roles never share a program, a map or a decision.
2. **Observe-only, provably.** Every measurement program returns the hook's pass verdict on every path:
   - TCX: `TCX_NEXT`;
   - cgroup socket hooks: allow;
   - tracepoints and `sock_ops`: no verdict exists.

   Beyond that, no measurement program:
   - modifies a packet or a socket;
   - redirects traffic;
   - writes a map that Cilium or ztunnel reads.

   A measurement fault can lose data. It can never change traffic.
3. **Packaged in the CMTC node DaemonSet.** The DaemonSet has two containers:
   - the unprivileged node agent (inventory, generation/digest ACKs, bounded probes), unchanged;
   - a measurement loader with only the capabilities and mounts its hooks need: `CAP_BPF`, `CAP_PERFMON`, `CAP_NET_ADMIN` for TCX, bpffs, and the cgroup v2 mount for cgroup hooks.

   The loader is written in Go with cilium/ebpf, the current loader. The language choice stays open to the review in [Evidence and open questions](#evidence-and-open-questions).
4. **Node-wide and automatic.**
   - **Discovery:** the loader discovers enrolled workloads from a read-only source of truth. It never relies on an operator-written per-Pod configuration.
   - **Identity checks:** it attaches per workload. Every attachment keeps the frozen-identity checks of the current observer: Pod UID, network namespace inode, interface index and MAC, and the Cilium link and program IDs.
   - **Change:** it follows Cilium's program regeneration and Pod replacement.
   - **Mismatch:** a mismatch makes that workload's data unavailable. It never attributes data to the wrong workload.
5. **An independent witness.** The plane checks enforcement without trusting the components it checks. It reads kernel and packet facts, not Cilium's or ztunnel's own claims. Its evidence never sets `Protected` alone; `Protected` still requires authenticated proxy and effective-policy state inside Cilium.
6. **Metric rules.**
   - **Labels:** bounded to cluster, node, namespace, direction and a fixed class set. Per-Pod detail goes only into a rate-limited event stream, never into metric labels.
   - **Absence:** an absent hook or exporter reports unavailable, never a healthy zero.
   - **One reporter:** each event has exactly one reporter. Signals Cilium, Hubble, ztunnel or SPIRE already export are reused, not counted again.
   - **Durations:** measured with the monotonic clock (`bpf_ktime_get_ns`). Wall time is attached only at export.
   - **Self-cost:** the plane reports its own cost and pressure: program run time and count, map occupancy, event loss and attach state.
7. **The CMTC fence becomes a lab qualification tool.**
   - **Kept for:** deny-path tests on disposable workloads.
   - **Production gate:** the gate it prototyped now lives natively in Cilium (point 1).
   - **Not allowed:** the fence is not the production gate, and it never becomes a dynamic allow controller.

## Candidate signals

The eBPF measurement review ranks these candidates. None is accepted until it passes the acceptance gates below.

| Signal | Candidate hook | What it adds |
| --- | --- | --- |
| Outer packets and bytes | TCX on the workload veth (today's observer) | Volume per workload and direction |
| Egress outside the tunnel | TCX, bounded L3/L4 classification | An enrolled Pod sending anything but HBONE (15008) and documented exemptions |
| Plaintext on 15008 | TCX, first payload record type only | A first record that is not a TLS handshake |
| Original application tuple | `cgroup/connect4`/`6`, `sendmsg4`/`6` | The destination and port the application asked for, hidden by the tunnel at TCX |
| Connection quality | `sock_ops`, `sock:inet_sock_set_state`, `tcp:tcp_retransmit_skb` | Handshake latency, RTT, retransmits and resets, app-to-ztunnel and ztunnel-to-peer kept separate |
| Revocation window | Connection close joined with the agent's xDS ACK time | Measured time from a narrowed plan to the last packet of a closed connection |
| Drops outside Cilium | `skb:kfree_skb` with reason, enrolled namespaces only | Drops Cilium's own drop notifications do not count |
| Security events | Ring buffer, rate-limited | Per-incident detail without per-Pod metric labels |
| Self-measurement | `BPF_ENABLE_STATS`, map and ring-buffer counters | The plane's own cost and loss |

## Alternatives considered

- **Port the measurement into the Cilium agent.**
  - **Gains:** one loader, and Cilium-managed hook ordering.
  - **Costs:** the witness then shares a process with what it checks, which loses its independence.
  - **Not rejected.** It stays an option for individual signals that need Cilium's internal state. Hubble remains the source for flows it already covers.
- **No eBPF; component metrics only.** This cannot see the original application tuple, egress outside the tunnel, plaintext on 15008 or drops outside Cilium. Rejected.
- **Keep the eBPF as a temporary prototype** (the superseded direction). Rejected by the operator mandate.

## Risks

- **TCX ordering.** An external TCX program is not a stable Cilium extension API. An observe-only program cannot change a verdict, but a wrong position could hide traffic from it. The loader verifies the full chain on every sample, as the observer does today.
- **cgroup multi-program semantics.** Next to Cilium's own cgroup programs, run order and the result of combining verdicts must be confirmed from `kernel/bpf/cgroup.c` before any cgroup hook ships.
- **Attach-to-pin window.** `BPF_LINK_CREATE` and `BPF_OBJ_PIN` are separate syscalls. A crash between them loses that attachment's data. This is acceptable for measurement: it fails as unavailable, not as a false zero.
- **Privilege.** The loader container is privileged in a narrow, explicit set. The node agent container stays unprivileged.

## Acceptance gates

- **No verdict:** a test proves every program's return value on every path. Traffic is identical with the plane attached and detached.
- **Attribution:** node-wide discovery attaches only to enrolled workloads with matching frozen identity. Pod, IP, ifindex and sandbox reuse never misattribute data.
- **Recovery:** loader restart, Cilium agent restart and regeneration, node reboot and drain each end with every enrolled workload attached again, or reported unavailable.
- **Cardinality:** a bound on series per node, tested.
- **No double counting:** each metric's reporter is named in the metric contract (`observability/v2/metrics/`, in progress), and no event is counted twice.
- **Freshness:** stale or absent data is unavailable on the dashboards.
- **Footprint:** run time and memory are measured under load and recorded.
- **Separation:** no signing-key access, identity minting, policy mutation or second traffic proxy.

## Evidence and open questions

- The current observer counts one frozen workload per node configuration (`internal/datapath/observer_linux.go:24-36`). It reads only `skb->len` and returns `TCX_NEXT` (`internal/datapath/bpf/observer.c`). The fence returns `TCX_DROP` unconditionally (`internal/datapath/bpf/fence.c`).
- At TCX, traffic of a ztunnel-enrolled Pod is HBONE to 15008. Upstream Cilium documents that "L4 policies won't work except for directly targeting the ztunnel HBONE port (15008)" ([ztunnel encryption](https://docs.cilium.io/en/latest/security/network/encryption-ztunnel/)).
- The lab runs `bpf-lb-sock=false`, so a cgroup connect hook sees a Global Service VIP, not the backend. ztunnel selects service backends in userspace (fork `src/state.rs:324`, `:356`).
- Open, under review:
  - the feature ranking and first increment;
  - Go (cilium/ebpf) versus Rust (aya) for the loader;
  - the read-only discovery source;
  - cgroup multi-program semantics.
