**Status:** Proposed; decision direction from static source review on 2026-10-23, current state added 2026-10-25. Architecture/security approval pending.

## Decision direction

Distinguish desired enrollment, label application, local enrollment, identity readiness and fresh enforcement evidence. Protected requires verified Cilium enforcement and expected peer identity/policy for the supported profile. Missing/stale evidence is Unknown, PendingEnforcement or Blocked with a reason.

## Source evidence and gaps

The [pinned proxy comparison](../../research/MESH_MTLS_COMPARISON.md) shows missing authorization references are skipped, and an empty effective ALLOW set permits traffic unless a DENY matches. The [integration contract](../CILIUM_ZTUNNEL_CONTRACT.md) therefore requires a persistent admission hold across policy delivery, restart and resync; local ZDS or separate xDS ACKs cannot supply that guarantee alone.

V03 shows asynchronous enrollment and a ZDS success/cache path; V07 shows empty authorization resources. Neither establishes first-packet safety or remote authorization. The endpoint-created callback logs failures; that is not a fail-closed guarantee.

## Alternatives and trade-offs

Admission/readiness cannot prevent arbitrary packets from running pods. Require a Cilium-owned gate through startup, relabel, trust-generation changes, restart and unenrollment; do not add broad pre-enrollment exceptions.

## Current state (2026-10-25)

- A Cilium-owned gate is deployed in our fork: a Required endpoint drops every packet until release, then allows only TCP 15008 (`bpf/lib/ztunnel_admission.h`). Release follows the compiled plan's ACK on the current ADS stream.
- With `REQUIRE_INBOUND_MTLS=true` (set in the deployed ztunnel), an empty effective ALLOW set denies a protected workload (`src/state.rs:762-768` in the ztunnel fork). The upstream allow-on-empty behavior above no longer applies to protected workloads.
- The race, crash, restore and teardown tests below have not run on the deployed build.

## Acceptance gates

Capture race stress, failed SVID/ZDS setup, UID recreation, proxy crashes and Cilium restore. Prove unauthorized traffic cannot escape before enforcement or during teardown. Expire status and bind it to UID/generation/version. Namespace status or a port-15008 connection cannot satisfy this gate.

Evidence IDs refer to the [Cilium v1.20.4 audit](../../research/SOURCE_AUDIT.md). The current-state section reports deployed and tested facts; it does not claim `Protected` or qualify any gate below. Mark Accepted only after explicit architecture/security approval.
