## Cluster-first development — Codex, Cursor and Claude

Use this loop for every implementation increment: **edit → run against `cmtc-a`/`cmtc-b` → test traffic, failures and recovery → package the verified change**. All delegated agents must receive this rule. Local package tests support this loop; they do not replace live integration.

Run Go controllers and helpers directly against the explicit kind APIs where supported. Coordinate one writer for each resource and avoid a second active reconciler. Use the Ubuntu toolchain and selected owned nodes for Linux datapath code. Use complete compatible binaries and BPF assets when testing that path. Do not package an application image merely to discover a basic integration failure. Toolchain containers remain valid for compilation and Linux tests. After the live path works, containerize it: build the image in CI (`.github/workflows/images.yaml`), push it to GHCR, deploy it by its GHCR digest and repeat the affected checks with that exact image before release or a Protected claim. A local registry image (`scripts/lab/local-registry.sh`) is allowed only for a short test, by judgement; remove it from the nodes afterwards (`ctr -n k8s.io images rm`), because local images filled the nodes before (operator, 2026-10-27). The lasting deployment is always the GHCR digest.

Keep source, compiler and lab leases explicit. Preserve unrelated applications, signer state and the existing security gates. Test activation is authorized on the two owned clusters; a successful activation is not proof of workload mTLS. Record actual positive, rejection and recovery results.

## Simplicity — no unrequested complexity (operator, 2026-10-27)

We are building an automated system. Keep it as simple as the stated goal allows. The labs are trusted clusters: only trusted operators can reach them, so do not design against in-cluster users who can create Certificates, RBAC or other objects. Use platform defaults (for example, cert-manager's built-in auto-approval) unless the operator asks for something else. Do not add a component, controller, policy engine, webhook, gate script or approval step on your own initiative; ask in one line first. Before calling a setting "the design", check `git log -S` and the operator's decisions; an earlier agent's choice is not a requirement. Removing unrequested complexity is in scope.
