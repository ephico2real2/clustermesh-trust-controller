CI runs and publication are deferred under [AGENTS.md](../../AGENTS.md); this page records the provenance and behavior of the capture harness. The dashboards it walks are the v1 dashboards under `observability/`, which stay current until `observability/v2/` lands.

The user requested the behavior of the existing PoC browser-walk action and demo55 capture workflow. Sources are pinned to `ephico2real2/cilium-implementation-poc` commit `22fb6e14c0cca8c78af1f072d1e89ebaea6a916b`:

- [Composite action](https://github.com/ephico2real2/cilium-implementation-poc/blob/22fb6e14c0cca8c78af1f072d1e89ebaea6a916b/.github/actions/browser-walk/action.yml).
- [Page walker](https://github.com/ephico2real2/cilium-implementation-poc/blob/22fb6e14c0cca8c78af1f072d1e89ebaea6a916b/scripts/capture/walk.js) and [YAML page spec](https://github.com/ephico2real2/cilium-implementation-poc/blob/22fb6e14c0cca8c78af1f072d1e89ebaea6a916b/scripts/capture/lab.yaml).
- [Demo55 CI](https://github.com/ephico2real2/cilium-implementation-poc/blob/22fb6e14c0cca8c78af1f072d1e89ebaea6a916b/.github/workflows/demo55-ci.yaml) and [Chrome file-wait helper](https://github.com/ephico2real2/cilium-implementation-poc/blob/22fb6e14c0cca8c78af1f072d1e89ebaea6a916b/demos/shared/browser-shot.sh).

`walk.cjs` copies the reference walker with these adaptations: CommonJS extension for this repository's module configuration, attribution, opt-in HTTPS-error ignoring (the CMTC lab uses HTTP loopback forwards), capture-name validation and a version-neutral Grafana DOM comment. The action's `env-json` variables expand directly from JSON without shell evaluation. Its data-driven YAML/JSON pages, resolver map, login/actions, lazy-panel scrolling, named No data exceptions, panel/text expectations, PNGs and failed-page exit status are preserved. CMTC's generated spec additionally marks accepted empty security panels as feature evidence **BLOCKED**, separately from rendering; `walk-results.json` retains both verdicts. Ordinary custom specs keep the original meaning of their allowed No data cases.

The prepared image is Ubuntu 24.04 Noble with Playwright **1.63.0**, matching the reference action, pinned to manifest `sha256:eff16c30e6f3f4af0a03fa4b706120d5e9b0891c344a27d64559aff5900a4a27`. The npm package and js-yaml **4.1.0** are lockfile-pinned. A Chromium launch smoke check and browser tests for a real HTML panel fixture, unexpected empty data, missing text and retained failure PNGs run during image construction. No browser-package cache can substitute for the OS libraries: they are installed in the Ubuntu image itself.

`capture.mjs` verifies CMTC's actual two-cluster telemetry, then writes a page spec from the provisioned dashboards. Implemented metrics must have data. Every permitted missing future metric is named with its reason in `walk-spec.json`. The two consolidated pages retain the original nine domains. Only named planned panels may be empty in Operations; no implemented Observe signal may be missing. Native mTLS panels require a separate SPIRE fixture and can be required with `CMTC_REQUIRE_NATIVE_MTLS=true`. The generated spec records each allowed absence reason and one absolute `from`/`to` window, which can be supplied with `CMTC_CAPTURE_FROM_MS` and `CMTC_CAPTURE_TO_MS`. The imported application must show the expected remote backend; its text is asserted without stretching a small response into a dashboard-sized PNG. `index.json`, metric assertions, the spec and walk verdict are retained alongside dashboard PNGs.

The local composite action retains the walker exit code, publishes evidence first and then enforces the verdict. `publish.sh` follows demo55's unique timestamp/run/attempt folder and retry-on-new-tip behavior, using a separate temporary Git checkout and no force push. An explicit allowlist publishes PNGs, browser verdict logs, timeline/load manifests and per-round query/range/verdict JSON onto **ci-captures**; kubeconfigs, container records and arbitrary artifact files stay local. Immutable commit URLs embed images directly in the job summary. The full artifact remains available even after failed assertions. CI capture commits use the requested ephico2real2 author/committer identity; an ephemeral workflow token authenticates CI publication without copying human SSH keys into the runner.

Local Linux use: `make capture-image lab-capture`. To walk a custom spec, run `CMTC_WALK_SPEC=path/to/pages.yaml make lab-capture`; this mode does not require the CMTC port forwards. To publish locally, explicitly provide the GitHub CI-style publication environment and token to `publish.sh`; ordinary local captures do not publish.

## Screenshots during load

CI starts all eight six-minute Fortio Jobs before it waits for their running init containers. The timeline runner freezes the cluster, Job, Pod and container identities. It captures Operations and Workload Security in both themes at 45, 135 and 225 seconds after that freeze. Each round has a 75-second deadline and checks the same eight processes before, during and after capture. The query range starts after all eight streams are active. Raw Prometheus results, browser timestamps and the fixed range are retained. Final Fortio results are required separately. The collector checks the frozen Job, Pod, node, image, container and start time before and after exact-Pod log reads. It stages logs until all eight streams pass.

Run `python3 scripts/capture/test_load_timeline.py` for timing, incarnation, query and publication tests. Run `python3 scripts/capture/test_collect_frozen_load.py` for terminated-process and log-collection tests. For a real local trial, use `load.sh start`, then `load_timeline.py --run-dir artifacts/load/<run> --out artifacts/<capture>`, then `load.sh collect`. On this MacBook, the Podman VM shares `/private/tmp`; use a task-owned copy of the same scripts there. The repository path under `/Users` is not mounted. Set paired loopback `CMTC_GRAFANA_URL` and `CMTC_APP_URL` forwards, `CMTC_CAPTURE_ENGINE=podman` and the exact built `CMTC_CAPTURE_IMAGE`. Preserve the existing kind provider. Local trials do not publish images or screenshots automatically.
